# CLAUDE.md: контекст проекта MKGA

Файл для Claude Code. Описывает, что это за проект, что сделано и что делать дальше.

## Что за проект

«MAKE KOMPAS GREAT AGAIN» (MKGA): открытый набор модов для КОМПАС-3D и маленький хаб, который находит, ставит и запускает моды (по образцу Addon Manager в FreeCAD и реестра плагинов Obsidian). Автор: Фёдор, студент (робототехника). Язык общения: русский. Проект неофициальный, с АСКОН не связан.

Главная цель ближайших недель: первый настоящий мод «Метизы и фитинги» (`mods/fasteners`), затем перенос в моды уже существующих инструментов автора.

## Устройство репозитория

- `mkga/manifest.py`: манифест мода `mkga-mod.json` и его проверка.
- `mkga/registry.py`: реестр `registry/registry.json` (id, repo, tag, sha256), поиск.
- `mkga/installer.py`: установка из zip с проверкой хеша, защитой от zip-slip, заменой старой версии.
- `mkga/runner.py`: `run_mod()` и `ModContext` (ленивое `ctx.kompas()`).
- `mkga/core/kompas.py`: подключение к запущенному КОМПАСу через COM (API5 + API7), `Kompas.version`. Проверено на v24 (подключение, версия).
- `mkga/core/safe_io.py`: безопасная запись с откатом (`ctx.session(...)`, `track`, `delete` в корзину, `dry_run`), журнал `python -m mkga history`, откат `undo`. Моды НЕ пишут файлы пользователя напрямую.
- `mkga/gui.py`: окно хаба на tkinter. Окно открывается (проверено на Windows, tk 8.6), функции кнопок не проверены.
- `mods/_template`, `mods/fasteners`: шаблон и заготовка мода.
- `docs/ARCHITECTURE.md`: формат манифеста, реестра, модель безопасности.

## Команды

```
python -m unittest discover -s tests -t .      # 56 тестов, КОМПАС не нужен
python tools/validate_registry.py
python -m mkga validate mods/_template
python -m mkga run-dev mods/_template          # мод из папки; нужен Windows, ЗАПУЩЕННЫЙ КОМПАС, pywin32
```

## Среда автора

- Windows, ноутбук fedor-redmibook, КОМПАС-3D v24 (SDK и справка SDK установлены).
- По прошлым чатам у автора уже есть свои наработки (на его машине, не в репозитории): `kompas_core.py`, `kompas_param.py` (управление КОМПАСом через COM), конвертер «КОМПАС → v22» на tkinter, самодельный «Комплектовщик», скрипты оформления ЕСКД (обозначения СНАБ.XXXXXX.NNN, разделы спецификации, материалы), параметрические скрипты деталей (вставки, зажимы). Их надо найти и перенести в моды.
- В КОМПАСе автора может не быть штатного «Комплектовщика документов».

## Принципы и маршрут

Базовые правила проекта («Не убий», стабильность, открытость, проверяемость, версии КОМПАСа):
`docs/PRINCIPLES.md`. Маршрут и статусы: `docs/ROADMAP.md`. Перед любой правкой сверяться с ними.
Коротко: файлы пользователя не ломаются (изменения в памяти, запись на диск только с откатом и
предпросмотром, удаление только в корзину), мод не показывает блокирующих окон КОМПАСа, моды
независимы, всё честно помечается «проверено / не проверено».

## Правила работы

- Исходные файлы КОМПАС пользователя не трогать: работать с копиями или новыми папками `_<дата>` / `(copy)`.
- Результат проверять самому: журналы, PNG-превью модели, сверка массы и объёма с расчётом. Не просить автора присылать скриншоты, если можно проверить скриптом.
- Данные стандартов брать из первоисточников и указывать источник. Базы и модели АСКОН не копировать. Неподтверждённые значения не добавлять.
- Не использовать слово «КОМПАС» так, будто проект официальный: в README есть дисклеймер, сохранять его.

1. Запустить `python -m mkga run hello-kompas` при открытом КОМПАСе v24, исправить подключение.

3. Создать репозиторий на GitHub, запушить, подставить ссылку на реестр.
4. Мод `fasteners`: каталог и поиск, затем построение деталей (DIN 912, 7991, 933, гайки, шайбы).
5. Перенести свои старые инструменты автора в моды.
