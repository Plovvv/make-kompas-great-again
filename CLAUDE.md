# CLAUDE.md: контекст проекта MKGA

Файл для Claude Code. Описывает, что это за проект, что сделано и что делать дальше.

## Что за проект

«MAKE KOMPAS GREAT AGAIN» (MKGA): открытый набор модов для КОМПАС-3D и маленький хаб, который находит, ставит и запускает моды (по образцу Addon Manager в FreeCAD и реестра плагинов Obsidian). Проект неофициальный, с АСКОН не связан.

Язык: документация и интерфейс на русском, имена в коде на английском.

Текущий этап: ядро, единый стиль, хаб, exe, запуск из меню КОМПАС и первый мод «Каталог комплектующих» (40 типов: крепёж, шайбы, штифты, кольца, вставки, стойки, Т-гайки, фитинги push-in; свои имена) готовы (см. `docs/ROADMAP.md`, `mods/components/README.md`). Дальше: первый выпуск мода в каталог, сверка таблиц с оригиналами, ещё типы и новые моды.

## Устройство репозитория

- `mkga/manifest.py`: манифест мода `mkga-mod.json` и его проверка.
- `mkga/registry.py`: реестр `registry/registry.json` (id, repo, tag, sha256), поиск.
- `mkga/installer.py`: установка из zip с проверкой хеша, защитой от zip-slip, заменой старой версии.
- `mkga/runner.py`: `run_mod()` и `ModContext` (ленивое `ctx.kompas()`).
- `mkga/core/kompas.py`: подключение к запущенному КОМПАСу через COM (API5 + API7), `Kompas.version`. Проверено на v24 (подключение, версия).
- `mkga/core/safe_io.py`: безопасная запись с откатом (`ctx.session(...)`, `track`, `delete` в корзину, `dry_run`), журнал `python -m mkga history`, откат `undo`. Моды НЕ пишут файлы пользователя напрямую: это проверяет `mkga/guard.py` (`python -m mkga check mods`, в CI). Документы КОМПАСа сохраняются через `Kompas.save_as(session, doc, path)`.
- `mkga/core/constants.py`: константы КОМПАСа, нужные модам (182, СГЕНЕРИРОВАНО `python tools/gen_constants.py`, вручную не править; новые добавлять в группы генератора). Использование: `from mkga.core import constants as C; C.ksDocumentPart`. `mkga/core/typelib.py`: чтение констант из библиотеки типов (только для разработки). `connect()` работает без `gencache`: позднее связывание принудительное (`force_late_binding`, не зависит от кэша gen_py на машине); выходные параметры API5: `out_ints`; `Kompas.new_document/close_document` (закрыть без сохранения можно только созданный нами документ). `Kompas.is_study/is_home/is_spds`: редакция.
- `tools/build_exe.py`, `tools/mkga.spec`: сборка exe (PyInstaller в изолированном `build/venv`), подробно `docs/DISTRIBUTION.md`. В сборку включены вся стандартная библиотека и все модули `mkga` (моды грузятся из папки пользователя), иначе мод падает на импорте. `mkga/ui/icon.py`: иконка (рисуется сама).
- `AGENTS.md`: вход для ИИ-агентов (ведёт сюда). Шаблоны issue/PR и метки: `.github/`. Проверка на других версиях КОМПАС: `docs/VERIFICATION.md`, матрица `docs/COMPATIBILITY.md`; результаты вносить в матрицу только после живых тестов.
- `mkga/release.py`, `mkga/verify.py`: выпуск и проверка модов (`mkga pack`, `mkga verify-registry`), см. `docs/WRITING_MODS.md`. Релиз воспроизводим; тег `v<версия манифеста>`; архив называется `<id>-<тег>.zip`.
- `mkga/core/model3d.py`: построение 3D-деталей (эскиз, выдавливание, вырез, вращение, свойства, `verify_volume`), только проверенное на живом КОМПАСе; подробно `docs/MODEL3D.md`. Справочник по API: `python tools/inspect_api.py find|show`. Новая операция без живого теста с расчётом объёма в слой не попадает.
- `mkga/core/versions.py`: правило версий (проверено / предупреждение / отказ) и таблица возможностей `FEATURES` (пока пуста, только подтверждённые факты). `mkga/core/fake.py`: фейковый КОМПАС (`--fake-kompas`). `mkga/core/settings.py`: `ctx.settings`.
- `mkga/ui/`: единый стиль (`docs/UI_STYLE.md`): `theme.py` (своя тема ttk, палитры LIGHT/DARK, DPI, `theme.px`, `theme.card`), `raster.py` (рисование скруглений на чистом Python), `window.py` (`ModWindow`: каркас окна мода с предпросмотром, журналом, действиями в рабочем потоке), `demo.py` (`python -m mkga ui-demo [--dark]`). Окна мод делает на `ModWindow`, размеры только через `theme.px`, внутри карточек стили `Card.*`. Особенности ttk (плитки 9-slice, фон виджета, потоки) описаны в UI_STYLE.md: читать перед правкой темы.
- `mkga/ui/hub.py`: окно хаба (`python -m mkga gui`): каталог, установленные, история с откатом, тема; на `ui/base.py` (общая основа окон). Логика без интерфейса: `mkga/hub_model.py` (строки каталога, состояния, история), запуск модов отдельным процессом: `mkga/launcher.py`. `mkga/gui.py` тонкая обёртка. Адрес реестра: `mkga/config.py` (реестр в репозитории проекта).
- `mkga/console.py`: UTF-8 для перенаправленного вывода (без него русский текст падает на Windows в CI и в запуске модов из хаба).
- `mods/_template`: шаблон мода. `mods/components`: **мод «Каталог комплектующих»** (каталог из 40 типов DIN/ISO и покупных изделий, свои имена, чертёж, создание детали с нужным именем): `mkga_components/` (`shapes.py` формы и точные объёмы, `catalog.py` таблицы и имена, `builder.py` создание, `drawing.py` чертёж, `ui.py` и `custom.py` окно), данные `data/standards/*.json` (один файл на стандарт, источник размеров в файле), `docs/ADDING_PARTS.md` (как добавить свою деталь). Новая форма детали только вместе с живым тестом `tests/test_live_components.py`. Тесты, открывающие окно мода, не запускают `run()` настоящего мода (mainloop).
- `mkga/kompas_menu.py`: пункты MKGA в меню КОМПАС («Приложения → Утилиты») правкой `KOMPAS.kit.config` при закрытом КОМПАС, с откатом (`python -m mkga kompas-menu`, кнопка в хабе), `docs/KOMPAS_MENU.md`.
- `mkga/core/com_iface.py`: вызовы интерфейсов, которых нет в основном IDispatch (грани, менеджер свойств): QueryInterface + memid из библиотеки типов. В `model3d.py` теперь есть дуга, грани, `thread()` (условное изображение резьбы), `set_title`, `set_object_type`, `set_spec_section` (раздел 25 или 30: объект спецификации в детали), `verify_planar_area`; факты и ловушки: `docs/MODEL3D.md` п. 10-17.
- `docs/ARCHITECTURE.md`: формат манифеста, реестра, модель безопасности.

## Команды

```
python -m unittest discover -s tests -t .      # 364 теста, КОМПАС не нужен (тесты окон пропускаются без дисплея)
python tools/validate_registry.py
python -m mkga validate mods/_template
python -m mkga pack mods/_template --repo owner/name   # собрать релиз мода, хеш и запись для реестра
python -m mkga check mods                      # страж: нет записи файлов в обход ctx.session
python -m mkga run-dev mods/_template --fake-kompas   # без КОМПАСа
MKGA_LIVE_KOMPAS=1 python -m unittest tests.test_live_kompas tests.test_live_model3d tests.test_live_components -v   # живая проверка, нужен запущенный КОМПАС
python -m mkga ui-demo --fake-kompas [--dark]  # демо окна мода (пишет только во временную папку)
python -m mkga run-dev mods/_template          # мод из папки; нужен Windows, ЗАПУЩЕННЫЙ КОМПАС, pywin32
```

## Принципы и маршрут

Базовые правила проекта («Не убий», стабильность, открытость, проверяемость, версии КОМПАСа):
`docs/PRINCIPLES.md`. Маршрут и статусы: `docs/ROADMAP.md`. Перед любой правкой сверяться с ними.
Коротко: файлы пользователя не ломаются (изменения в памяти, запись на диск только с откатом и
предпросмотром, удаление только в корзину), мод не показывает блокирующих окон КОМПАСа, моды
независимы, всё честно помечается «проверено / не проверено».

## Правила работы

- Версия мода (`mkga-mod.json`): новый стандарт или таблица, исправление размеров, мелкие правки это третья цифра (0.4.0 → 0.4.1). Вторая цифра только для заметной новой возможности (новый режим, новая функция окна). Версию не менять при каждом добавлении одного винта.

- Файлы КОМПАС пользователя меняются только через `ctx.session` (снимок, откат, предпросмотр, корзина), см. `docs/PRINCIPLES.md`. Для экспериментов лучше работать с копиями или новыми папками.
- Результат проверять самому: журналы, PNG-превью модели, сверка массы и объёма с расчётом. Не просить пользователя присылать скриншоты, если можно проверить скриптом.
- Данные стандартов брать из первоисточников и указывать источник. Базы и модели АСКОН не копировать. Неподтверждённые значения не добавлять.
- Не использовать слово «КОМПАС» так, будто проект официальный: в README есть дисклеймер, сохранять его.
