# Сборка и распространение (exe)

Пользователю собранной версии не нужен Python: папка `MKGA` содержит `MKGA.exe` (окно хаба, без консоли) и
`mkga-cli.exe` (все команды, с консолью). Размер около 37 МБ папка и 19 МБ zip.

## Сборка

```powershell
python tools/build_exe.py            # собрать, проверить и упаковать
python tools/build_exe.py --clean    # пересоздать окружение сборки
python tools/build_exe.py --no-smoke # без проверки собранного
```

Всё нужное (PyInstaller, pywin32, tzdata из `tools/build-requirements.txt`) ставится в изолированное окружение
`build/venv` внутри проекта, системный Python не затрагивается. Результат: `build/dist/MKGA/` и
`build/MKGA-<версия>-windows.zip`; папка `build/` в `.gitignore`. Сборка занимает около минуты.

Скрипт сам рисует иконку (`mkga/ui/icon.py`, без внешних файлов) и пишет свойства файла (версия, описание,
лицензия) в `build/version_info.txt`.

## Что проверяется автоматически

После сборки `build_exe.py` прогоняет собранное в окружении, где **в PATH нет Python**: версия, страж правил,
сборка релиза мода, установка мода из архива, запуск мода, мод, импортирующий ВСЕ модули `mkga` и строящий деталь
на фейковом КОМПАС (проверяет, что в сборку попало всё, что нужно модам), окно хаба живёт 8 секунд.

Проверено вручную на живом КОМПАС-3D v24 (25.11.2026): `MKGA.exe --mods-dir <папка> run <мод>` с выводом в трубу, ровно
как хаб запускает моды в собранной версии; мод `hello-kompas` и мод, строящий цилиндр через `mkga.core.model3d` со
сверкой объёма. Документы пользователя не менялись.

## Устройство и ограничения

- **onedir, а не onefile.** Моды запускаются отдельными процессами из того же `MKGA.exe`; onefile распаковывал бы себя
  при каждом запуске (медленно, чаще ложные срабатывания антивирусов).
- **Что доступно модам в exe:** вся стандартная библиотека (включена целиком, потому что моды загружаются из папки
  пользователя и PyInstaller не видит, что они импортируют), все модули `mkga` (`collect_submodules`, иначе
  `mkga.core.model3d` не попадает в сборку), `pywin32` и `tzdata`. **Других пакетов нет:** хаб показывает, что мод требует
  недоступные пакеты (`requires` в манифесте), и такой мод не запускает.
- Двойной щелчок по `MKGA.exe` открывает хаб. Без консоли `print` уходит «в никуда», ошибки видны в журнале хаба.
- exe не подписан, поэтому Windows SmartScreen может показать предупреждение при первом запуске («Подробнее» → «Выполнить в
  любом случае»). Подпись кода (платный сертификат) в планах.
- Собранная версия не обновляется сама: новая версия это новый zip (автообновление хаба в планах).

## Публикация

Zip собирается локально. Автоматическая сборка и публикация в релизы GitHub (workflow на Windows-раннере) в планах:
нужен релиз, и это публикация в репозитории, поэтому делается осознанно.
