# Единый стиль интерфейса

Решение для всех окон MKGA (хаб и моды). Принципы проекта: [PRINCIPLES.md](PRINCIPLES.md).

## Решение

**tkinter + ttk со СВОЕЙ современной темой на основе `clam`, без внешних пакетов.** Скругления, поля,
флажки, плашки, полосы прокрутки рисуются при запуске растеризатором на чистом Python
(`mkga/ui/raster.py`) под текущий масштаб экрана. Поэтому вид одинаково чёткий на 100%, 150% и 200%.
Есть светлая и тёмная палитры.

| Что | Где |
|---|---|
| Палитры, тема, шрифты, DPI, цвет заголовка окна | `mkga/ui/theme.py` (`apply_theme`, `LIGHT`, `DARK`, `Theme.px`, `Theme.card`) |
| Растеризатор картинок (SDF, PNG, 9-slice) | `mkga/ui/raster.py` |
| Общая основа окон (потоки, журнал, статус КОМПАСа, подтверждения) | `mkga/ui/base.py` (`WindowBase`) |
| Каркас окна мода | `mkga/ui/window.py` (`ModWindow`) |
| Окно хаба | `mkga/ui/hub.py` (`HubWindow`), логика без интерфейса: `mkga/hub_model.py`, запуск модов: `mkga/launcher.py` |
| Образец для авторов модов | `mkga/ui/demo.py`, запуск `python -m mkga ui-demo [--dark] [--fake-kompas]` |

Что даёт тема: скруглённые кнопки трёх видов (обычная, главная `Primary`, `Ghost` без рамки), поля с
подсветкой фокуса, карточки, плашки статуса (`PillOk/PillError/PillMuted`), флажки и переключатели,
тонкие полосы прокрутки, прогресс, плоская таблица, тёмный блок журнала, значки на кнопках (шрифт
Segoe Fluent Icons, `mkga.ui.theme.ICONS`; без шрифта подписи остаются без значков).

## Почему так

Решающий довод: **масштаб экрана**. На ноутбуках обычно 125–200% (на машине разработки 200%, 192 DPI).
Готовые темы с PNG фиксированного размера (например `sv-ttk`) на таком экране масштабируются плохо:
в их трекере давно открыта проблема [Scaling issues with HighDPI](https://github.com/rdbende/Sun-Valley-ttk-theme/issues/18).
Встроенная тема `vista` масштабируется правильно, но выглядит как обычная форма Windows (это был первый
вариант, он признан слишком «топорным»).

| Вариант | Итог | Причина |
|---|---|---|
| **Своя тема, картинки рисуются под DPI** | выбран | Красиво, без зависимостей, чётко на любом масштабе, обе палитры. Цена: код темы (~450 строк) и аккуратность с особенностями ttk (ниже). |
| tkinter + `vista` | отклонён как основа | Надёжно, но вид стандартной формы Windows. |
| tkinter + `sv-ttk` | отклонён | Проблемы масштабирования, не красит заголовок окна Windows. |
| CustomTkinter | отклонён | Нельзя `--onefile` (файлы данных), лишняя зависимость ([вики проекта](https://github.com/TomSchimansky/CustomTkinter/wiki/Packaging)). |
| PySide6 / Qt | пока нет | Лучший вид, но exe около 115 МБ ([пример](https://dev.to/kerfiq/pyside6-vs-electron-why-i-shipped-a-118-mb-windows-desktop-tool-not-a-250-mb-cross-platform-one-2gfl)) и заметно больше кода. Путь на будущее, если tkinter не хватит. |

Как устроены похожие проекты: [FreeCAD Addon Manager](https://wiki.freecad.org/Std_AddonMgr/en) это один
диалог со списком и кнопкой «Установить / Обновить» (установка и обновление одна операция), с фоновой
проверкой обновлений и локальным кэшем каталога; это берём для окна хаба. Образцов оконного интерфейса
для приложений на API КОМПАСа найти не удалось, поэтому ориентир: Windows 11 Fluent (плоские карточки,
скругления, значки Segoe Fluent) и окна самого КОМПАСа по расположению.

## Правила окна мода

1. **Каркас `ModWindow`.** Шапка (название, версия мода, плашка статуса КОМПАСа), слева карточка
   «Параметры», справа карточка «Что будет сделано с файлами» (предпросмотр) и тёмный журнал, внизу
   статус, прогресс и кнопки.
2. **Предпросмотр до записи.** Мод, который что-то меняет, имеет кнопки «Предпросмотр» (`dry_run`) и
   «Выполнить», показывает список через `win.set_changes(session.changes)`, и всегда рядом есть
   «Отменить последнее» (`BackupStore.undo`). См. PRINCIPLES, п. 1.
3. **Действия в рабочем потоке.** `win.add_action(текст, fn, icon=..., primary=...)`: окно не зависает,
   COM подготовлен, КОМПАС подключается в том же потоке. Из `fn` нельзя трогать виджеты: сообщения через
   `ctx.log`, список изменений `win.set_changes`, статус `win.set_status`. Значения полей читаются в
   главном потоке: `add_action(..., params=lambda: (...))`.
4. **Ошибки не роняют окно.** Ошибка действия попадает в журнал красным, в статусе «ошибка».
5. **Версия КОМПАСа.** Предупреждение о непроверенной версии показывается диалогом в главном потоке.
6. **Никаких модальных окон КОМПАСа** (`ksMessage`).
7. **Размеры только через `theme.px(n)`** (n как при 96 DPI). Размер окна не больше 90% экрана.
8. **Стили внутри карточки:** `Card.TLabel`, `Card.Muted.TLabel`, `Card.TEntry`, `Card.TCombobox`,
   `Card.TCheckbutton`, `Card.TRadiobutton`, `Card.TButton`. Обычные контейнеры внутри карточки это
   `CardInner.TFrame`. Сама карточка создаётся `theme.card(parent)`, у неё отступ задаётся виджетом.
9. **Тексты.** Русский, кнопки это глаголы («Выполнить», «Отменить последнее»), заголовок окна
   «<Мод>: MKGA (неофициальный)», ошибки по-человечески (что случилось и что делать).
10. **Цвета не задавать вручную:** брать из `theme.palette`.

## Особенности ttk, которые нельзя забывать (выстраданы при отладке)

- **Середина картинки должна быть крупной.** ttk закрашивает середину 9-slice картинки плитками
  размером с неё. Картинка с серединой в 2 px на большой карточке даёт сотни тысяч отрисовок (секунды на
  кадр, а на 100% DPI зависание). Поэтому картинки растягиваются `Image.stretched()` до серединки в
  40 «логических» px, а минимальный размер элемента задаётся `width`/`height`.
- **Фон самого виджета = фон родителя**, иначе он закрасит скруглённые углы. Для кнопок и полей внутри
  карточек есть варианты `Card.*`.
- **Имена элементов**, которые виджет ищет сам, должны оканчиваться на `.thumb`, `.trough`, `.pbar`.
- **Объекты Tk (картинки, шрифты, переменные) нельзя удалять из рабочего потока:** сборщик мусора в
  рабочем потоке роняет Tcl. Не вызывать `gc.collect()` в рабочих потоках; при закрытии окна
  `ModWindow` освобождает объекты в главном потоке.
- Скругления рисуются 1 раз при запуске (~0,1–0,2 с).
- Цикл обработки сообщений окна (`_pump`) не должен падать от ошибки обработчика: исключение пишется в журнал,
  иначе окно перестаёт обновляться, а рабочий поток зависает на ожидании ответа.
- Размер окна не больше 90% ширины и 82% высоты экрана, окно открывается по центру.

## Хаб

- Боковая навигация (`Nav.TButton` / `NavActive.TButton`), страницы «Каталог», «Установленные»,
  «История изменений». Справа от списка карточка выбранного мода.
- Хаб НЕ выполняет код модов у себя: мод запускается процессом `python -m mkga run <id>` (в собранном
  exe то же через `sys.executable`), вывод читается построчно в журнал. Окна модов открываются отдельно.
- Тема хранится в настройках хаба (`data/hub/settings.json`): `system`, `light`, `dark`. Смена темы
  пересоздаёт окно (`run_hub`), страница, поиск и загруженный каталог сохраняются.
- Все диалоги подтверждений из рабочего потока идут через `WindowBase.ask(сообщение, вопрос)`.
- Кнопки в карточке деталей включаются по состоянию мода и на время действия отключаются.

## Ограничения и открытое

- Tk не поддерживает разные масштабы на разных мониторах: используется системный масштаб.
- Цвет заголовка окна (Windows 11) подстраивается под тему; на Windows 10 заголовок остаётся системным.
- Первый кадр большого окна (2080×1400 px на экране 200%) рисуется около секунды: стоит оптимизировать.
