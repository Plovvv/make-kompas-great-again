# Как написать и выпустить мод

Руководство для автора мода. Правила проекта: [PRINCIPLES.md](PRINCIPLES.md). Работа ИИ-агента с проектом:
[../CLAUDE.md](../CLAUDE.md).

## 1. Что такое мод

Папка с файлом `mkga-mod.json` и Python-файлом с функцией `run(ctx)`. Хаб запускает мод ОТДЕЛЬНЫМ процессом,
поэтому сбой мода не роняет хаб и другие моды. Три вида (`kind`): `app` (своё окно), `macro` (один запуск),
`library` (код для других модов).

Быстрый старт: скопируйте `mods/_template` в `mods/<id>` (или в свой репозиторий) и поправьте манифест. Образец готового мода с окном, данными в JSON и живыми тестами: `mods/fasteners` (код модуля кладите в свой пакет с уникальным именем, например `mkga_<id>/`, чтобы не пересечься с другими модами по имени).

```
my-mod/
  mkga-mod.json      манифест
  main.py            точка входа: def run(ctx)
  README.md          что делает, на каких версиях КОМПАС проверен, откуда данные
```

## 2. Манифест

| Поле | Описание |
|---|---|
| `id` | латиница в нижнем регистре, цифры, дефис; 2–40 символов; уникален в каталоге |
| `name`, `description`, `author`, `license` | показываются в хабе |
| `version` | `МАЖОР.МИНОР.ПАТЧ`; тег релиза обязан быть `v<версия>` |
| `kind` | `app`, `macro` или `library` |
| `entry` | относительный путь к `.py` с `run(ctx)` |
| `kompas_versions` | версии КОМПАС, на которых мод РЕАЛЬНО запускали, например `[24]`; не заявляйте непроверенное |
| `tags` | слова для поиска в каталоге |

Проверка: `python -m mkga validate <папка>`.

## 3. Что получает мод: `ctx`

| Что | Зачем |
|---|---|
| `ctx.kompas()` | подключение к запущенному КОМПАСу (версия, документы, `Kompas.new_document`); сверка с `kompas_versions` идёт сама |
| `ctx.log(text)` | сообщение пользователю (в журнал окна или консоль); НЕ используйте модальные окна КОМПАСа |
| `ctx.session(title)` | единственный путь к записи файлов: снимок, откат, предпросмотр, корзина |
| `ctx.settings` | настройки мода в JSON в папке данных |
| `ctx.mod_dir`, `ctx.data_dir` | папка мода и папка его данных |

## 4. Файлы пользователя: только через сессию

```python
def run(ctx):
    with ctx.session("Переименовать детали") as s:      # при ошибке всё откатывается автоматически
        s.write_text(path, text)                        # изменение (с копией для отката)
        s.delete(old_path)                              # удаление только в корзину
        ctx.kompas().save_as(s, doc, new_path)          # сохранение документа КОМПАС: тоже через сессию
```

`ctx.session(title, dry_run=True)` ничего не меняет и даёт `s.changes` для предпросмотра. Пользователь видит
операцию в хабе («История изменений») и может её отменить. Прямые `open(..., "w")`, `os.remove`, `shutil.*`,
`doc.Save` и т. п. ловит страж `python -m mkga check <папка>`; сборка релиза с такими вызовами не пройдёт.
Подробности: [PRINCIPLES.md](PRINCIPLES.md), п. 1.

## 5. Окно мода

```python
from tkinter import ttk
from mkga.ui.window import ModWindow

def run(ctx):
    win = ModWindow(ctx, "Мой мод", version="0.1.0")
    ttk.Label(win.params, text="Имя", style="Card.TLabel").grid(row=0, column=0)
    win.add_action("Предпросмотр", preview, icon="view")
    win.add_action("Выполнить", apply, primary=True, icon="play")
    win.mainloop()
```

Действия выполняются в рабочем потоке (окно не зависает); из них не трогайте виджеты, пользуйтесь `ctx.log`,
`win.set_changes`, `win.set_status`. Правила и стили: [UI_STYLE.md](UI_STYLE.md). Образец: `python -m mkga ui-demo`.

## 6. 3D-детали

`mkga.core.model3d.Part`: эскиз, выдавливание, вырез, вращение, свойства, `verify_volume`. Только проверенное на
живом КОМПАСе, подробности и особенности КОМПАСа: [MODEL3D.md](MODEL3D.md). Справочник по API:
`python tools/inspect_api.py find|show`.

**Важно про собранную версию (exe):** модам доступны вся стандартная библиотека, все модули `mkga`, `pywin32` и `tzdata`. Другие пакеты в `requires` в exe недоступны: хаб предупредит и не запустит такой мод. Если нужен сторонний пакет, мод работает только из исходников.

## 7. Тестирование без КОМПАСа и с ним

- Фейковый КОМПАС: `python -m mkga run-dev <папка> --fake-kompas`; в тестах `mkga.core.fake.make_fake_kompas()`.
- Живая проверка на вашей версии: свой тест по образцу `tests/test_live_kompas.py` (только в НОВЫХ документах,
  запись только во временную папку).
- Результат сверяйте с расчётом (объём, масса), а не «на глаз».
- Данные стандартов берите из первоисточников и указывайте источник; базы и модели АСКОН не копируются.

## 8. Выпуск

1. Поднимите `version` в манифесте, проверьте `validate` и `check`.
2. Соберите релиз: `python -m mkga pack <папка> --repo <владелец>/<репозиторий>` (тег по умолчанию `v<версия>`).
   Архив воспроизводим: тот же код даёт тот же хеш. Печатаются хеш и готовая запись для реестра.
3. Опубликуйте релиз на GitHub с тегом `v<версия>` и приложите файл `dist/<id>-v<версия>.zip` ПОД ЭТИМ ЖЕ ИМЕНЕМ.
   Это можно автоматизировать шаблоном [templates/release-mod.yml](templates/release-mod.yml).
4. Добавьте запись в каталог: `python -m mkga pack <папка> --repo ... --add-to-registry registry/registry.json`
   в форке этого репозитория и откройте pull request. Обновление версии мода это тоже pull request.
5. Проверьте до отправки: `python -m mkga verify-registry --only <id>` (скачивает релиз и сверяет хеш, манифест,
   версию и страж правил; нужен интернет).

## 9. Что проверяет каталог

Автоматически (`.github/workflows/registry.yml`): хеш архива, безопасность zip (пути, ссылки, размер),
манифест, совпадение `id` и версии с записью, страж правил. Это ловит случайные ошибки, но НЕ злой умысел:
перед слиянием нового мода код читает человек, а проверка не заменяет это чтение.

## 10. Контрольный список

- [ ] `mkga validate` и `mkga check` без замечаний
- [ ] `kompas_versions` только проверенные версии; README описывает проверку и источник данных
- [ ] запись файлов только через `ctx.session`, есть предпросмотр и «Отменить»
- [ ] нет сети во время работы мода и скачивания кода
- [ ] тег `v<версия>`, архив приложен под именем `<id>-<тег>.zip`, хеш в реестре совпадает
